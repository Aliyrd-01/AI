# MCP Client в n8n — Туториал

## Что такое MCP?

**MCP (Model Context Protocol)** — это протокол, который позволяет AI-агенту вызывать внешние инструменты (tools). Работает по принципу «клиент — сервер»:

| Компонент | Что это | В нашем случае |
|-----------|---------|----------------|
| **MCP Client** | Нода в n8n, которая подключается к серверу | Нода `MCP Client` |
| **MCP Server** | Программа, которая предоставляет инструменты | `server.mjs` на localhost:3001 |

> [!IMPORTANT]
> MCP Client сам по себе **ничего не делает**. Он лишь «переходник» между AI Agent и внешним MCP-сервером. Без запущенного сервера — инструментов не будет.

## Запуск — пошагово

Нужно **3 терминала** (вкладки PowerShell):

### Терминал 1: ngrok

```powershell
ngrok http 5678
```

Скопируйте HTTPS-адрес (например `https://xxxxx.ngrok-free.app`).

---

### Терминал 2: n8n

```powershell
$env:WEBHOOK_URL="https://xxxxx.ngrok-free.app/"
npx n8n
```

> [!WARNING]
> Замените `xxxxx` на ваш реальный адрес из ngrok. Без `WEBHOOK_URL` Telegram-триггер выдаст ошибку «An HTTPS URL must be provided for webhook».

---

### Терминал 3: MCP-сервер

```powershell
cd C:\Users\valen\.gemini\antigravity\scratch\mcp_test
node server.mjs
```

Ожидаемый вывод:
```
MCP server running on http://localhost:3001/sse
```

## Настройки в n8n

### Нода MCP Client

| Параметр | Значение |
|----------|----------|
| **Server Transport** | `SSE` (Sent Server Events) |
| **Endpoint** | `http://localhost:3001/sse` |

### Связи между нодами

```
Telegram Trigger → AI Agent → (выход)
                      ↑
              Chat Model (OpenRouter / Gemini)
              Memory (Simple Memory)
              Tools ← MCP Client ← Code Tool (если есть)
```

## Проверка

Отправьте боту в Telegram:

- `"Скажи который сейчас час, используя инструмент get_time"` — вызовет инструмент `get_time`
- `"Поздоровайся с Валентином через инструмент greet"` — вызовет инструмент `greet`

Если MCP Client загорелся зелёной галочкой — всё работает!

## Порядок остановки

Останавливайте в обратном порядке (Ctrl+C в каждом терминале):

1. MCP-сервер (терминал 3)
2. n8n (терминал 2)
3. ngrok (терминал 1)

> Не используйте `taskkill /f /im node.exe` без необходимости — это убивает ВСЕ процессы Node.js и может повредить базу данных n8n.

## Зачем нужен MCP — примеры применения

На нашем примере MCP-сервер предоставлял 2 простых инструмента (`get_time`, `greet`). Но в реальных проектах MCP используется для гораздо большего:

### 1. Доступ к базам данных
MCP-сервер подключается к PostgreSQL/MySQL и даёт агенту возможность делать SQL-запросы через чат:
> *«Покажи последние 10 заказов из базы»* → агент вызывает `query_database`

### 2. Работа с файловой системой
Агент может читать, создавать и редактировать файлы на сервере:
> *«Создай отчёт и сохрани в файл report.txt»* → агент вызывает `write_file`

### 3. Интеграция с API
Подключение к любому внешнему API (CRM, ERP, биржи, погода):
> *«Какой сейчас курс биткоина?»* → агент вызывает `get_crypto_price`

### 4. Управление инфраструктурой
DevOps-задачи: деплой, мониторинг, управление серверами:
> *«Перезапусти сервер staging»* → агент вызывает `restart_server`

### 5. Работа с документами
Поиск по внутренней базе знаний компании:
> *«Найди в нашей документации инструкцию по возвратам»* → агент вызывает `search_docs`

> [!TIP]
> **Главная идея MCP:** вместо того чтобы писать отдельные интеграции для каждого AI-инструмента (ChatGPT, Claude, n8n), вы один раз пишете MCP-сервер — и он работает с любым MCP-клиентом. Это как USB — один стандарт для всех устройств.
